# Шаг 4. Потоковая обработка данных

В проекте для шага 4 используется Faust.

Сервис читает товары из Kafka, проверяет их по списку запрещённых товаров и дальше пропускает только разрешённые товары.


1. Товары читаются из топика `products.raw`.
2. Список запрещённых товаров хранится в Kafka через топик `products.banned`.
3. Управление списком сделано через CLI: можно добавить товар в запрет или убрать его.
4. Faust worker держит локальную таблицу `banned_products`.
5. Разрешённые товары отправляются в `products.validated`.
6. Запрещённые или невалидные товары отправляются в `products.rejected`.

## Как работает

Поток данных:

`products.raw -> product-filter-faust -> products.validated`

Если товар запрещён:

`products.raw -> product-filter-faust -> products.rejected`

Список запретов обновляется отдельным потоком:

`CLI -> products.banned -> product-filter-faust -> banned_products table`

Проверка идёт по `product_id`. Если `product_id` есть в таблице `banned_products`, товар дальше не проходит.

## Как запустить

Из корня проекта:

```bash
docker compose up -d product-filter-faust
```

Посмотреть логи сервиса:

```bash
docker compose logs -f product-filter-faust
```

## Управление списком запрещённых товаров

Добавить товар в список запрещённых:

```bash
uv run python -m services.product_filter_service.cli_ban.banned_cli ban 12346 --name "Nova X10" --reason "Запрещён к продаже"
```

Убрать товар из списка запрещённых:

```bash
uv run python -m services.product_filter_service.cli_ban.banned_cli unban 12346
```

CLI отправляет событие в топик `products.banned`. Faust worker читает этот топик и обновляет свою таблицу.

## Проверка

Проверить, что запрещённый товар попал в `products.rejected`:

```bash
docker exec -it \
  -e JMX_PORT= \
  -e KAFKA_JMX_PORT= \
  -e KAFKA_JMX_OPTS= \
  kafka-0 kafka-console-consumer.sh \
  --bootstrap-server kafka-0:9092 \
  --topic products.rejected \
  --from-beginning \
  --group products-consumer-group \
  --consumer-property security.protocol=SASL_SSL \
  --consumer-property sasl.mechanism=PLAIN \
  --consumer-property 'sasl.jaas.config=org.apache.kafka.common.security.plain.PlainLoginModule required username="consumer" password="consumer-secret";' \
  --consumer-property ssl.truststore.location=/bitnami/kafka/config/certs/kafka.truststore.jks \
  --consumer-property ssl.truststore.password=123456 \
  --consumer-property ssl.truststore.type=JKS \
  --consumer-property ssl.endpoint.identification.algorithm=HTTPS
```

Проверить, что разрешённые товары попали в `products.validated`:

```bash
docker exec -it \
  -e JMX_PORT= \
  -e KAFKA_JMX_PORT= \
  -e KAFKA_JMX_OPTS= \
  kafka-0 kafka-console-consumer.sh \
  --bootstrap-server kafka-0:9092 \
  --topic products.validated \
  --from-beginning \
  --group products-consumer-group \
  --consumer-property security.protocol=SASL_SSL \
  --consumer-property sasl.mechanism=PLAIN \
  --consumer-property 'sasl.jaas.config=org.apache.kafka.common.security.plain.PlainLoginModule required username="consumer" password="consumer-secret";' \
  --consumer-property ssl.truststore.location=/bitnami/kafka/config/certs/kafka.truststore.jks \
  --consumer-property ssl.truststore.password=123456 \
  --consumer-property ssl.truststore.type=JKS \
  --consumer-property ssl.endpoint.identification.algorithm=HTTPS
```

Проверить через Elasticsearch, что разрешённый товар дошёл до хранения:

```bash
curl -s -X POST "http://localhost:9200/products.validated/_search?pretty" \
  -H "Content-Type: application/json" \
  -d '{"query":{"match_all":{}}}'
```

Если нужно найти товар по имени, поле лежит внутри `raw_json`:

```bash
curl -s -X POST "http://localhost:9200/products.validated/_search?pretty" \
  -H "Content-Type: application/json" \
  -d '{"query":{"match":{"raw_json.name":"Планшет TabOne 11"}}}'
```
